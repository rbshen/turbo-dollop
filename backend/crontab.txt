# Fathom cron schedule. Install with: crontab crontab.txt
# (This replaces the whole crontab for this user -- merge by hand with
# `crontab -e` if other jobs already exist outside this project.)
#
# To change either schedule, edit the "minute hour" fields below -- nothing
# in the scripts themselves needs touching for a schedule change.

# Nightly S&P 500 fundamentals refresh, 2:00 AM server time.
# Reuses the existing cache-aware fetch pipeline (get_step1_data /
# get_step2_data / get_step4_data / get_step5_data / get_summary) -- first
# run after this project's initial deploy does a full cold-cache fetch
# (~7,000 FMP calls, ~30 min); every run after that is mostly cache hits,
# since get_or_fetch only calls FMP for tickers whose cache has actually
# gone stale. Its own log (with per-ticker detail and the run summary)
# lives at backend/logs/nightly_fundamentals_fetch.log; the redirect below
# is only a catch-all for a crash before that log gets configured.
#
# Invoked as `-m pipeline.nightly_fundamentals_fetch`, not a direct script
# path -- these scripts live inside the pipeline/ package now (backend
# structure reorg) and import sibling modules with absolute-from-backend
# paths (e.g. `from db import engine`), which only resolve when the
# interpreter is launched with backend/ itself on sys.path. `-m` run from
# backend/ (via the `cd` below) does that; `python pipeline/foo.py` does
# not -- it puts pipeline/ on sys.path instead and fails with
# ModuleNotFoundError. Confirmed by actually running both forms.
0 2 * * * cd /home/shen/fathom/backend && /home/shen/.local/bin/uv run python -m pipeline.nightly_fundamentals_fetch >> /home/shen/fathom/backend/logs/nightly_fundamentals_fetch_cron.log 2>&1

# Nightly full-universe TickerScore recompute, 2:50 AM server time -- after
# the nightly fetch above (which usually finishes well under 30 min on a
# warm cache, and already recomputes scores for its own S&P 500/Dow
# tickers at the end of its per-ticker loop). This sweep's real value is
# every OTHER tracked ticker (any ticker ever viewed ad hoc, outside the
# index universe) -- built after the IREN/SEZL/POOL investigation found
# those tickers' TickerScore rows could go stale/incomplete (e.g. computed
# before all step inputs finished caching) with nothing ever revisiting
# them. Cache-only -- zero FMP calls, no rate-limit pacing needed, safe to
# run anytime. See pipeline/nightly_score_recompute.py.
50 2 * * * cd /home/shen/fathom/backend && /home/shen/.local/bin/uv run python -m pipeline.nightly_score_recompute >> /home/shen/fathom/backend/logs/nightly_score_recompute_cron.log 2>&1

# Weekly S&P 500 constituent list refresh (Wikipedia scrape), Sundays at
# 1:00 AM server time -- runs before the nightly fetch above so a freshly
# added/removed ticker is reflected the same night. Index membership only
# changes a handful of times a year, hence weekly rather than nightly.
0 1 * * 0 cd /home/shen/fathom/backend && /home/shen/.local/bin/uv run python -m scrapers.refresh_sp500_list >> /home/shen/fathom/backend/logs/sp500_list_refresh_cron.log 2>&1

# Weekly Dow Jones constituent list refresh (Wikipedia scrape), Sundays at
# 1:05 AM server time -- staggered a few minutes after the S&P 500 refresh
# above (both still run before the 2 AM nightly fetch) so the two Wikipedia
# scrapes don't overlap.
5 1 * * 0 cd /home/shen/fathom/backend && /home/shen/.local/bin/uv run python -m scrapers.refresh_dow_list >> /home/shen/fathom/backend/logs/dow_list_refresh_cron.log 2>&1

# Weekly maintenance window, Sundays 1:10-1:25 AM -- staggered 5 minutes
# apart (same pattern as the two list refreshes above), all still ahead of
# the 2 AM nightly fetch. See backend/OPS_RUNBOOK.md for what each of these
# does and what to check if one fails.

# Cache pruning: deletes FundamentalsCache rows older than
# Settings.cache_retention_days (default 180) -- distinct from the 7-day
# staleness window, which only controls refetching. See pipeline/prune_cache.py.
10 1 * * 0 cd /home/shen/fathom/backend && /home/shen/.local/bin/uv run python -m pipeline.prune_cache >> /home/shen/fathom/backend/logs/prune_cache_cron.log 2>&1

# Log rotation for backend/logs/ -- no system logrotate involved, see
# pipeline/rotate_logs.py's own docstring for why.
15 1 * * 0 cd /home/shen/fathom/backend && /home/shen/.local/bin/uv run python -m pipeline.rotate_logs >> /home/shen/fathom/backend/logs/rotate_logs_cron.log 2>&1

# Fixture-contamination audit -- promoted from manual-only to a weekly

# CLAUDE.md's "Ad-hoc reproduction scripts must not touch the real

20 1 * * 0 cd /home/shen/fathom/backend && /home/shen/.local/bin/uv run python -m pipeline.audit_fixture_contamination >> /home/shen/fathom/backend/logs/audit_fixture_contamination_cron.log 2>&1

# Stale-data health check: reports (not silently) how many universe tickers
# haven't had a fresh nightly refresh recently. See pipeline/stale_data_health_check.py.
25 1 * * 0 cd /home/shen/fathom/backend && /home/shen/.local/bin/uv run python -m pipeline.stale_data_health_check >> /home/shen/fathom/backend/logs/stale_data_health_check_cron.log 2>&1

# Invalid-ticker purge: deletes FundamentalsCache (and any TickerScore) rows
# for tickers with a confirmed-empty FMP profile fetch (FMP responded, but
# with no companyName at all -- its actual "no such symbol" shape), never a
# real index member. Built after the IREN/SEZL/POOL investigation found a
# handful of these (typos, stale test-fixture placeholders) sitting as
# permanent dead weight. See pipeline/purge_invalid_tickers.py for the exact
# criteria and why a real-but-temporarily-unreachable ticker (an FMP outage,
# a real access-tier gap like BRK.B's known 402) is never a match.
30 1 * * 0 cd /home/shen/fathom/backend && /home/shen/.local/bin/uv run python -m pipeline.purge_invalid_tickers >> /home/shen/fathom/backend/logs/purge_invalid_tickers_cron.log 2>&1

# Monthly price-target-consensus snapshot, 3:00 AM server time on the 1st of
# each month -- FMP has no historical price-target series of its own (unlike
# grades-historical, already a ready-made monthly series), so this
# accumulates one going forward for the Analyst Ratings tab's price-target
# history line and Recommendation Details "N ago" Target column. Both start
# empty and fill in as this job runs. Monthly (not nightly) to match
# grades-historical's own monthly grain and keep the snapshot table's growth
# bounded.
0 3 1 * * cd /home/shen/fathom/backend && /home/shen/.local/bin/uv run python -m pipeline.monthly_price_target_snapshot >> /home/shen/fathom/backend/logs/monthly_price_target_snapshot_cron.log 2>&1

# Daily SQLite backup, 3:30 AM server time -- after the 2 AM nightly fetch,
# with a 1.5hr buffer even for a cold-cache run. Compressed, timestamped
# copy of fathom.db to backend/backups/ (gitignored); keeps the last 14
# (two weeks). See pipeline/backup_db.py.
30 3 * * * cd /home/shen/fathom/backend && /home/shen/.local/bin/uv run python -m pipeline.backup_db >> /home/shen/fathom/backend/logs/backup_db_cron.log 2>&1
