# Nightly S&P 500 fundamentals refresh, 2:00 AM server time.
# Reuses the existing cache-aware fetch pipeline (get_step1_data /
# get_step2_data / get_step4_data / get_step5_data / get_summary) -- first
# run after this project's initial deploy does a full cold-cache fetch
# (~7,000 FMP calls, ~30 min); every run after that is mostly cache hits,
# since get_or_fetch only calls FMP for tickers whose cache has actually
# gone stale. Its own log (with per-ticker detail and the run summary)
# lives at backend/logs/nightly_fundamentals_fetch.log; the redirect below
# is only a catch-all for a crash before that log gets configured.
#
# Invoked as `-m pipeline.nightly_fundamentals_fetch`, not a direct script
# path -- these scripts live inside the pipeline/ package now (backend
# structure reorg) and import sibling modules with absolute-from-backend
# paths (e.g. `from db import engine`), which only resolve when the
# interpreter is launched with backend/ itself on sys.path. `-m` run from
# backend/ (via the `cd` below) does that; `python pipeline/foo.py` does
# not -- it puts pipeline/ on sys.path instead and fails with
# ModuleNotFoundError. Confirmed by actually running both forms.
# When the `fundamentals` data group (or the FMP master switch) is off, this job
# records a real "skipped" run (not a success) -- see CLAUDE.md "Data groups".
0 2 * * * cd /home/shen/fathom/backend && /home/shen/.local/bin/uv run python -m pipeline.nightly_fundamentals_fetch >> /home/shen/fathom/backend/logs/nightly_fundamentals_fetch_cron.log 2>&1

# AM server time -- placed AFTER Liquidity Zone's own full 3:25-3:35
# window (not squeezed into the gap before it), with its own dedicated
# ~15-minute allocation ending by 3:55, when backup_db (below) now runs.

# "~15-30s worst-case" cost, based on a flawed pre-shipping benchmark that

# fetches a full 2-year lookback and replays the whole state machine from
# scratch every run (unlike BB+RSI's 60-day/latest-day-only shape) -- a

# Monthly Momentum snapshot (3mo/6mo/12mo composite trailing-return ranking
# over the Moat-rated universe), 3:05 AM server time -- staggered from the
# price-target snapshot (2026-09-11 cron audit finding #5/A: both used to fire
# at the literal same minute, 0 3 1 * *, an avoidable SQLite writer-lock
# contention risk; the price-target job has since moved to daily 2:10).
# Tried daily across the 1st-5th of each month rather than pinned to the
# 1st, since the lookback windows must anchor to a completed month's FINAL
# close (running at 3am on the calendar 1st would be before that day's own
# session even opens), and a holiday can push the real first trading day of
# the month past the 1st. The script itself (helpers/trading_calendar.py::
# resolve_month_end_anchor) checks whether today is genuinely the first
# NYSE trading day of the month and no-ops (still a "success" heartbeat)
# on every other day in this window. See pipeline/monthly_momentum_snapshot.py.
5 3 1-5 * * cd /home/shen/fathom/backend && /home/shen/.local/bin/uv run python -m pipeline.monthly_momentum_snapshot >> /home/shen/fathom/backend/logs/monthly_momentum_snapshot_cron.log 2>&1
