# ---------------------------------------------------------------------------
# Overlap protection (2026-10-13). Every command below runs under `flock -n -E 99` on its own
# lock file in backend/logs/locks/ (one file per job, created on first use; `mkdir -p` makes the
# directory, so a fresh checkout works). A run that starts while the previous run of the SAME job
# still holds the lock does not start: it appends ONE line to the job's own log ("<date> skipped
# <job>: the previous run is still going") and exits. Exit code 99 is flock's "lock busy" code
# (-E 99), so a job that fails on its own is not mistaken for a skip. The job itself is untouched;
# the lock is released when it exits, however it ends. A skipped run writes no CronRunLog row, so
# the Scheduled jobs page shows that night's run as missing until the next one. Different jobs never
# block each other. `flock` is /usr/bin/flock (util-linux). `%` is `\%` because cron turns a bare `%`
# into a newline.
# ---------------------------------------------------------------------------
# Nightly chain (server time = UTC): technical jobs 1:00-1:40 AM, fundamentals 2:00 AM,
# then sector/industry P/E 3:05, price-target 3:10, score recompute 3:25, backup 3:30. Schedule history: technical
# jobs 2:00-2:40 -> 12:00-12:40 on 2026-10-01 -> 1:00-1:40 on 2026-10-02, and fundamentals
# 2:55 -> 2:00 the same day (the Sunday maintenance block, 12:00-12:35 AM, now runs
# BEFORE the chain). Order reordered 2026-09-30: technical jobs first, fundamentals
# later (technical data is the higher priority). Order, each job in its own slot:
#   last close -> Weinstein + bar-cache fill -> Liquidity Zone (support/resistance)
#   -> BB+RSI -> Warren -> Sector ETF heatmap -> Market Breadth -> ETFs screener
#   -> FMP fundamentals -> sector/industry P/E snapshot -> analyst price-target -> score recompute -> SQLite backup
# (The earnings/dividends/splits cache is NOT in the nightly chain: it is a weekly Saturday job, see below.)
# Hard ordering constraints (pinned by tests/test_cron_wiring.py):
#   * the Weinstein/bar-cache job (pipeline.nightly_trend_calculation -- the "trend" name is
#     historical) fills the shared daily-bar cache; LP, Sector and Breadth read it warm
#   * BB+RSI before Warren (BB+RSI creates the 60d intraday row, Warren widens it)
#   * score recompute after Weinstein/BB+RSI/Warren, and before the backup
# Everything else is preference. Windows below are sized from observed CronRunLog
# durations; if a job is moved, keep its successor's slot at least as far out.
# Every command uses `-m package.module` (NOT a direct script path) run from
# backend/ via the `cd`: these scripts live in subpackages and import siblings
# with absolute-from-backend paths, which only resolve when backend/ is on
# sys.path. `python pipeline/foo.py` puts pipeline/ there instead and fails
# with ModuleNotFoundError.
# ---------------------------------------------------------------------------
